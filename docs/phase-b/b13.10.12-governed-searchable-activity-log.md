# B13.10.12 — Governed Searchable Activity Log

## Existing foundation

Enorsis already uses the canonical `AuditEvent` model for major governance and
business actions. The model already supports tenant scope, actor/user identity,
action, resource, outcome, reason, request ID, IP address, user agent,
before/after JSON, metadata and timestamp.

B13.10.12 adds a governed research interface over that evidence rather than
creating a second audit system.

## Access model

### Tenant Owner / Tenant Admin

Can access `/app/activity-log`.

The server always forces:

`tenantId = authenticated user's tenantId`

A Buyer tenant administrator therefore sees only Buyer-tenant evidence.
A Supplier tenant administrator therefore sees only Supplier-tenant evidence.

They cannot request another tenant by editing URL query parameters.

IP address and user-agent/device data are not returned in their activity-log
view.

### Platform Super Admin

Can search all tenants or filter to one tenant.

Advanced evidence includes:
- source IP address when captured
- browser/device user-agent when captured
- request/correlation identifier when captured

Historical records may show "Not captured" when the original audit-writing path
did not collect request metadata.

## Search

The Activity Log supports:

- free-text research
- action search
- resource-type search
- tenant filter for Platform Super Admin
- from date/time
- to date/time
- pagination

Free-text research can match:
- action
- actor label
- reason
- resource ID
- before JSON
- after JSON
- metadata JSON
- user name/email
- marketplace product name
- marketplace SKU/description/brand/model
- Purchase Request line/product description

This makes research such as `Industrial Safety Gloves` return audit events tied
to that offering and related Purchase Requests, subject to the viewer's tenant
scope.

## Search durability

`AuditEvent.searchText` is maintained by a PostgreSQL trigger. Existing rows are
backfilled, including current marketplace offering names where a historical
audit event references a marketplace offering.

## Request evidence

`getAuditRequestContext()` captures when available:
- `x-forwarded-for` / `x-real-ip`
- user-agent
- request ID / Vercel request identifier / Cloudflare ray

The increment wires request metadata into several high-value actions immediately:
- marketplace offering creation
- marketplace offering update when B13.10.10 is installed
- Purchase Request creation/submission
- Purchase Request approval/rejection/return
- tenant member role update when B13.10.6 is installed

The existing audit architecture remains the canonical source for all other
already-instrumented actions.

## Privacy and governance

IP addresses are treated as advanced security/audit evidence and are displayed
only to Platform Super Admin.

Tenant administrators cannot retrieve cross-tenant audit rows or advanced IP /
device evidence through the Activity Log query.
