# B13.10.4D — Direct Marketplace Media Uploads

## Purpose

Move marketplace product/service image bytes out of Next.js Server Actions and
Vercel Function request bodies.

## Previous flow

Browser -> Publish Offering Server Action -> Vercel Function -> Private Blob

This conflicted with Next.js Server Action body limits and Vercel Function
request-body limits for multi-image marketplace listings.

## New flow

1. Supplier publishes offering metadata.
2. Offering appears in Offering Visibility Controls.
3. Supplier selects up to the remaining 8-image gallery allowance.
4. Browser requests an authenticated Blob client-upload token.
5. Browser uploads image bytes directly to Private Vercel Blob.
6. Browser calls the authenticated media registration endpoint.
7. Enorsis verifies the blob with Blob `head()`.
8. Enorsis validates offering ownership, tenant self-supplier identity,
   content type, file size, image count and pathname.
9. Enorsis creates SupplierMarketplaceOfferingMedia.
10. First registered image becomes primary and updates imageRef.
11. Audit evidence is recorded.

## Security

The token route:
- requires an authenticated Enorsis session
- verifies the offering belongs to the active tenant
- verifies the offering belongs to the tenant self-supplier profile
- restricts content types to JPG, PNG and WebP
- limits each image to 8 MB
- scopes upload paths to the selected offering

The registration route independently re-validates:
- authenticated tenant
- offering ownership
- self-supplier ownership
- Blob pathname
- actual Blob content type
- actual Blob size
- 8-image maximum
- duplicate registration

## No schema migration

B13.10.4D reuses SupplierMarketplaceOfferingMedia and requires no new Prisma
migration.
