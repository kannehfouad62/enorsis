# B10.4 — Native Value Realization Adapter

B10.4 creates a real native Enorsis ProcurementValueInitiative from an
eligible human-governed autonomous value/savings draft.

Verified native Value Realization workflow:
- ProcurementValueInitiative supports initiative number, title, description,
  category, supplier/sourcing/contract linkage, owner, finance owner,
  executive sponsor, currency, baseline, target benefit, forecast benefit,
  probability, dates, assumptions and risks.
- New initiatives begin in QUALIFYING status.
- ProcurementBenefit records are separate and require methodology/evidence.
- Finance validation is a separate privileged action.
- Realized benefit is updated only after validation.

B10.4 behavior:
- accepts only targetWorkflow VALUE_REALIZATION
- creates ProcurementValueInitiative in QUALIFYING status
- maps autonomous savings estimate to target/forecast benefit
- maps modeled exposure to baseline
- maps confidence to probability
- sets current authorized user as owner
- uses USD
- binds the native initiative ID back to the autonomous execution chain
- writes decision and audit evidence

B10.4 explicitly does not:
- create realized savings
- submit a benefit claim
- create supporting evidence
- finance-validate a benefit
- alter realizedBenefitAmount
- claim value realization

Native route:
`/app/value-realization`

Adapter workspace:
`/app/governance/autonomous-execution/native-drafts/value-realization`

No Prisma migration is required because B10.4 uses existing native value-
realization and autonomous-governance models.
