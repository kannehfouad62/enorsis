# B13.3 — Predictive Inventory & Capacity Runtime Integration

This integration connects the existing predictive inventory and predictive
capacity engines to the B13.3 multi-engine governed runtime gateway.

## Existing behavior verified

Predictive Inventory:
`src/core/predictive-inventory/optimization-engine.ts`

Before integration, every generated `PredictiveInventoryOptimizationSignal`
was persisted with `createMany`.

Predictive Capacity:
`src/core/predictive-capacity/capacity-engine.ts`

Before integration, every generated `PredictiveCapacityPlanningSignal`
was persisted with `createMany`.

Neither engine had a confidence gate controlling persistence.

## Safety-preserving integration

Both engines now evaluate each candidate through:

`evaluateMultiEngineControlledConfidence(...)`

### OFF

All generated signals continue to persist.

This is behaviorally equivalent to the pre-B13.3 engines.

### SHADOW

All generated signals continue to persist.

The governed threshold is evaluated and traced, and disagreement with the
default comparison is recorded, but no signal is suppressed.

### ENFORCED

The governed threshold becomes authoritative.

Only signals passing the governed confidence gate are persisted.

## Decision paths

Inventory:

`MULTI_ENGINE_DECISION_PATHS.PREDICTIVE_INVENTORY`

Capacity:

`MULTI_ENGINE_DECISION_PATHS.PREDICTIVE_CAPACITY`

## Correlation evidence

Inventory traces include:
- optimization run ID
- inventory item ID
- SKU
- item name
- category
- risk level
- recommendation

Capacity traces include:
- capacity run ID
- scope type
- scope key
- scope label
- risk level
- recommendation

## Result payload additions

Both engine return values now include:

- `signalCount` — number actually persisted
- `candidateSignalCount` — total generated candidates
- `suppressedSignalCount` — suppressed only when ENFORCED

No Prisma schema change.
No migration.
