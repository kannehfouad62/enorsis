# B8.4 Permanent Prisma Index Naming Fix

Root cause:
PostgreSQL limits identifiers to 63 bytes. The automatically generated Prisma
index name for:

`@@index([tenantId, digitalTwinRunId, impactType])`

was truncated by PostgreSQL. Prisma then detected the physical truncated name
as different from the schema-derived name and repeatedly attempted to author a
new migration.

Permanent fix:
The schema now uses an explicit stable short database index name:

`@@index([tenantId, digitalTwinRunId, impactType], map: "PDigitalTwinImpact_run_type_idx")`

The included migration renames the already-existing database index to that
mapped name.

Going forward:
- use explicit short `map:` names for long @@index / @@unique definitions
- use `npx prisma migrate deploy` when an Enorsis patch already contains the
  migration directory
- reserve `npx prisma migrate dev --name ...` for authoring genuinely new local
  schema changes
