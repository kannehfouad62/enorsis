# B13.10.14 — Selected Approver & Governed Approval Escalation

Marketplace Purchase Request checkout now lets a requester select the first
accountable tenant approver.

The selection never overrides Membership.approvalLimitUsd.

If the selected approver has sufficient authority:
- Approve / Return / Reject remain available.

If the selected approver's authority is below the request USD equivalent:
- Approve is hidden/blocked.
- The approver sees "Approval authority exceeded".
- The approver can escalate only to another ACTIVE APPROVER whose
  approvalLimitUsd covers the request.

Escalation:
1. closes the insufficient-authority step with explicit escalation context,
2. creates a new sequential PENDING approval step,
3. leaves the Purchase Request UNDER_REVIEW,
4. sends in-app + email notification to the new approver,
5. records `purchase_request.approval_escalated` in AuditEvent.

The submission audit records:
- selected approver ID/email,
- selected approval limit,
- required USD amount,
- whether escalation is required.

The escalation audit records:
- original approver,
- original limit,
- required amount,
- original sequence,
- target approver,
- target limit,
- new sequence,
- comments,
- request/IP/user-agent context where captured.

No seller order is created until a valid final approval is completed.

No Prisma migration is required.
