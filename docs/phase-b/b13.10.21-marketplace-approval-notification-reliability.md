# B13.10.21 — Marketplace Approval Notification Reliability

## Observed problem

A Marketplace Purchase Request could be submitted with a persisted approver, but
the approval user received neither the Enorsis in-app notification nor the email
notification.

## Root hardening

### 1. Persisted approval is source of truth

The notification recipient is now resolved from the actual
`PurchaseRequestApproval` persisted for the Purchase Request after the database
transaction completes.

This prevents notification recipient drift between:

- checkout-selected approver
- approval-chain calculation
- persisted approval record

The approver User is then loaded fresh by ID before notification delivery.

### 2. Unified notifyUser path

Marketplace approval requests now use the same `notifyUser()` helper already
used by seller-order and buyer-order lifecycle notifications.

That helper creates:

- IN_APP delivery
- EMAIL delivery when the user has an email address

### 3. Built-in Resend EMAIL provider

The Enterprise Notification provider registry previously depended entirely on
runtime registration of EMAIL providers.

B13.10.21 adds a lazy built-in Resend EMAIL provider using:

- RESEND_API_KEY
- RESEND_FROM_EMAIL
- fallback WORKFLOW_EMAIL_FROM
- NEXT_PUBLIC_APP_URL for absolute action URLs

Existing custom provider registration still takes precedence.

### 4. Audit evidence

Marketplace PR approval notification produces:

- marketplace.purchase_request.approval_notification.sent
- marketplace.purchase_request.approval_notification.failed

The success record includes:

- Purchase Request ID
- request number
- persisted approver ID
- approver email
- approval sequence
- requested channels

## Expected flow

Marketplace checkout
→ Purchase Request persisted
→ PurchaseRequestApproval persisted
→ persisted approver resolved
→ EnterpriseNotification created
→ IN_APP delivered immediately
→ EMAIL delivered through Resend
→ approver sees notification and email
→ action URL opens the exact Purchase Request

No Prisma migration is required.
