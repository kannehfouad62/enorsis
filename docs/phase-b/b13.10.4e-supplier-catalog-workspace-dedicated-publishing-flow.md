# B13.10.4E — Supplier Catalog Workspace & Dedicated Publishing Flow

## UX objective

The Marketplace Catalog should scale to suppliers with tens, hundreds or
thousands of listings without forcing users to scroll past product cards to
find a large creation form.

## New structure

Supplier Command Center:

- Product & Service Catalog
- Publish Offering

Marketplace Catalog:

- search/filter listings
- view supplier listings
- manage images
- manage visibility and featured status
- prominent Publish Offering CTA

Dedicated publishing page:

`/app/marketplace/catalog/new`

The page contains the complete product/service metadata form and displays the
authenticated tenant's self-supplier identity.

## Publishing sequence

1. Supplier opens Publish Offering.
2. Supplier enters product/service metadata.
3. Enorsis creates the marketplace offering.
4. Enorsis redirects to Marketplace Catalog.
5. Supplier uploads product images using B13.10.4D direct Blob uploads.
6. Supplier manages primary image, visibility and featured state from catalog.

## Persona behavior

SUPPLIER:
- sees Manage Catalog and Publish Offering
- can create listings for its tenant self-supplier identity

BUYER_SUPPLIER:
- can use the same publishing flow through its self-supplier identity

BUYER:
- cannot access `/app/marketplace/catalog/new`
- does not see supplier publishing controls

## No schema migration

B13.10.4E is a presentation/workflow refinement and requires no Prisma schema
change.
