# B12.8 Predictive Procurement Runtime Integration

This integration intentionally preserves the existing predictive procurement
behavior discovered in `forecast-engine.ts`.

## Existing behavior

Before B12.8 integration, `generatePredictiveProcurementForecast()` persisted
every generated forecast signal. There was no confidence threshold deciding
whether a signal should be stored.

Therefore a runtime adoption layer must not introduce a threshold while OFF or
SHADOW.

## Corrected mode semantics

### OFF
- every generated signal is persisted
- policy resolution can still be traced
- no policy can suppress a signal
- behavior matches the pre-B12.8 engine

### SHADOW
- every generated signal is persisted
- governed threshold is evaluated
- differences are counted and traced
- governed result does not suppress a signal

### ENFORCED
- governed confidence threshold becomes authoritative
- signals that fail the governed gate are not persisted
- every decision is traced through B12.7
- B12.6 bounds and fallback rules remain in force

## Predictive procurement integration

Each generated forecast signal is passed to:

`evaluateControlledRuntimeConfidence(...)`

Trace correlation:
- correlationId = PredictiveProcurementForecastRun.id
- evidence includes signal type, scope key, label and risk level

The forecast result now also returns:
- `signalCount`: persisted signals
- `candidateSignalCount`: all generated candidate signals
- `suppressedSignalCount`: signals suppressed only when ENFORCED

No Prisma schema change.
No migration.
