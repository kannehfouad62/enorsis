# B10.5 — Native Inventory Rebalancing Adapter

B10.5 creates a real native Enorsis InventoryMovementLedger from an eligible
human-governed autonomous inventory-rebalancing draft.

Verified native inventory behavior:
- createInventoryMovement supports TRANSFER movements.
- quantity must be greater than zero.
- movement records are initially DRAFT.
- posting is a separate privileged action.
- only posting validates source/destination location requirements.
- only posting checks source availability.
- only posting decrements/increments inventory snapshots.
- only posting changes status to POSTED.
- only posting emits Inventory.MovementPosted events and activity.

B10.5 behavior:
- accepts only targetWorkflow INVENTORY_REBALANCE
- creates movementType TRANSFER
- leaves movement in DRAFT
- maps resource/inventory item ID and proposed quantity
- maps optional proposed source/destination locations if available
- maps proposed USD value to optional unit cost
- references the governed autonomous native draft
- binds the movement ID back to the autonomous execution chain
- writes decision and audit evidence

If locations are absent, the movement is still safely created as DRAFT; native
posting will remain impossible until required locations are completed.

B10.5 explicitly does not:
- post the movement
- decrement source stock
- increment destination stock
- override availability checks
- create inventory availability snapshots through posting
- resolve inventory exceptions

Native route:
`/app/inventory-operations`

Adapter workspace:
`/app/governance/autonomous-execution/native-drafts/inventory`

No Prisma migration is required because B10.5 uses existing native inventory
and autonomous-governance models.
