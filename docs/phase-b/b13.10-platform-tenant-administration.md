# B13.10 — Platform Tenant Administration

Purpose:
Provide a production UI for Platform Super Admin to provision and govern independent Enorsis tenants before manual UAT and commercial onboarding.

Routes:
- /app/settings/tenants
- /app/settings/tenants/[id]

Security:
- Platform Tenant Administration requires PLATFORM_SUPER_ADMIN.
- TENANT_OWNER and TENANT_ADMIN cannot enumerate or create other tenants.
- New tenant owners receive TENANT_OWNER and TENANT_ADMIN only.
- Customer tenant owners never receive PLATFORM_SUPER_ADMIN through this workflow.

Provisioning transaction:
Tenant
→ User upsert
→ Membership
→ TENANT_OWNER + TENANT_ADMIN
→ AuditEvent

Tenant lifecycle:
- PROVISIONING
- ACTIVE
- SUSPENDED
- ARCHIVED

UAT usage:
1. Platform Super Admin creates buyer tenant.
2. Platform Super Admin creates supplier tenant.
3. Each tenant owner signs in and configures /app/settings/organization.
4. Buyer and supplier users are created with tenant-scoped roles.
5. End-to-end commerce UAT proceeds through marketplace, PR, approval, PO, supplier acceptance, shipment, receipt, warehouse, inventory, invoice, match and payment.
