# B13.10.13a — Incremental Tenant-Admin Secure User Activation

This increment is built against the existing `tenant-user-activation` service
already present in Enorsis.

## Root cause fixed

`/app/settings/access` used a legacy invitation path that:

- required the tenant administrator to choose a temporary password
- immediately stored password credentials
- left the membership as `INVITED`
- did not call the existing tenant-user activation email service

This produced `INVITED WITH CREDENTIALS`.

## New identity

A brand-new email is now:

- created without password credentials
- assigned roles and organizational scopes
- stored as `INVITED`
- sent a single-use activation email using the existing
  `/activate-user-account?tenant=...&token=...` route
- activated only after the user chooses their own password

## Existing Enorsis identity

An existing user who already has credentials keeps the existing password.

When granted a new tenant membership:

- password is not overwritten
- roles/scopes are assigned
- membership becomes ACTIVE
- access addition is audit logged

## Recovery

Normal `INVITED` + no credentials:
- `Resend activation`

Legacy `INVITED` + credentials:
- `Reset & resend activation`

Reset recovery is limited to invited memberships and cannot be used by an
administrator to reset their own credentials.

## Evidence

The existing activation service now records:

- tenant.member.activation.invited
- tenant.member.activation.reset_invited
- tenant.member.activation.email.sent
- tenant.member.activation.email.failed
- tenant.member.activation.completed

No Prisma migration is required.
